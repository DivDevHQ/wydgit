Status: **open / unresolved**, target **0.3**. Recorded 2026-10-18 under
[Decision 0003](../decisions/0003-defer-managed-hosting-qualification-to-0.4.md).

## Investigation and closure requirements

Page-budget exhaustion is observed; precise delay attribution, causation and
mitigation remain unresolved. Distinguish this issue from sandbox Unix EPERM,
subprocess stdout loss and the native async-ID assertion. Do not classify it as
environmental solely because focused or ordinary-user reruns pass.

Use focused, instrumented reproductions before expensive full reruns. Preserve
exact runtime/execution context, concurrency, sanitized phase/error diagnostics,
commit/cancellation boundaries and failing logs. Any proposed correction must retain
bounded execution, storage consistency, cancellation and sibling isolation; raising
budgets, reducing concurrency or weakening assertions merely to obtain a pass is
not closure evidence. Require a demonstrated cause or bounded attribution, reviewed
mitigation and applicable focused/full regression evidence before resolving this
issue. No fix, acceptance waiver or deployment authorization is recorded here.

## Increment 7: bounded BackOffice correction (alpha.22)

Starting HEAD `23821a39e8e629e3764cda399a9198e47aacb2a6`, clean
`develop/0.3`; origin fetched and identical. Native baseline: focused BackOffice,
transport/resource/shared-ledger tests **103/103**; full suite **1479/1479**.
Restricted sandbox runs had listener/process failures and a Node native async-ID
assertion; these are separate from functional HTTP evidence. Logs:
`/tmp/alpha22-baseline-focused-native.log`, `/tmp/alpha22-baseline-full-native.log`.

Source inspection found a distinct reproducible defect: BackOffice checked the
HTTP deadline after dispatch, but created a fresh action ledger without the parent
deadline or response-disconnect guard, and bound services without an operation
control. Consequently expiration during authentication/authorization could still
admit an operation. BOREL-02 deterministically advances the clock at the authorization
boundary and asserts zero dispatches. The fix passes private native execution
options (never request JSON) through the existing action facade, checks admission,
clips the unchanged action ledger to the HTTP deadline, and binds the existing
completion control into canonical dispatch. Body collection uses the remaining
request allowance. Disconnected requests cannot publish late success or start a
later guarded service. All admitted native work is still awaited; stopped-App
maintenance remains excluded until settlement. No limit increases or mutation
retries were introduced.

`X-Wydgit-Action-Outcome` is conservative publication evidence: `rejected` means
no contributed service handler began, `completed` accompanies a validated successful
response, and `uncertain` means a handler began but success could not be published.
It does not certify rollback, exactly-once delivery or provider commit state. Gate's
nested private storage does not propagate an outer operation control: an already
admitted Gate handler may commit after cancellation. Store retains its own guarded
precommit checks. The caller must inspect state before retrying an uncertain write.
HTTP deadline exhaustion maps to sanitized 503 `HTTP.DEADLINE`; body byte/collection
bounds retain 413, action budget exhaustion retains 503 `SEWN.LIMIT`.

BOREL-01–05 cover preadmission deadlines, genuine zero-service-call exhaustion,
controlled async completion before/after the unchanged deadline, sanitized read
failure, eight concurrent requests, real TCP abort, and drain/maintenance exclusion.
BOHTTP-07 retains a genuine Gate mutation committed before the failed response,
with one invocation and an uncertain outcome. Existing UI tests retain no replay.

**Historical FrontEnd defect remains open.** Neither baseline reproduced it. The
Page path still reports 500 for an execution failure; changing that status would
not repair its cause. A bounded controlled await can legitimately exhaust the
1,000 ms wall-time ledger while counters remain below their ceilings, and cleanup
can then report follow-on LIMIT. Existing trusted meters distinguish time, counter,
guard and closed-ledger causes. There is no evidence of counter double charging in
this increment. The historical failure needs an instrumented failing full-load
trace: retain phase/span meters, add bounded host event-loop delay measurements if
needed, and distinguish provider wait from scheduling delay before deciding on a
budget-policy change. Pausing wall-time charging around I/O would change security
semantics and needs separately reviewed CPU/wall/deadline policy plus starvation,
provider cancellation and drain tests. It is not attempted here. No automatic
retry, universal idempotency, preemption or cross-process drain is claimed.

The initial new eight-request test also reproduced **401 under concurrent session
touches** twice (including an isolated run). Gate stores last-seen time through its
existing three-attempt optimistic directory update; competing reads can exhaust
that bound with GATE.CONFLICT. HTTP had collapsed every resolution failure to
invalid authentication and deleted a still-valid cookie. The narrow fix preserves
that bound and maps unavailable resolution (conflict/busy/I/O) to sanitized 503
SERVICE.FAILED without deleting credentials, both before and after action dispatch.
Genuine invalid sessions still return 401 and clear the cookie. BOREL-06 injects
each transient code and verifies recovery using the same credential. BOREL-04
qualifies eight siblings with completed or explicitly unavailable results, no false
401/403 or credential deletion, and at least one completed request. It does not
claim that all concurrent requests succeed. A separate Gate scheduling design would
be needed to guarantee successful admission at this contention; no directory-write
retry expansion, automatic action retry or new mutation queue was added.

Checkpoint validation: the first implementation full run was **1486 pass / 2 fail /
1488 total**, both stale launcher alpha.21 version expectations; these were
synchronized without changing runtime/security assertions. The broader final focused
launcher/transport/HTTP run passed **46/46**. Six unchanged FrontEnd deadline probes
passed **6/6 in each of two runs**, including execution under concurrent full-suite
load. BOREL-07 additionally proves expiration during pending canonical admission
prevents actual handler entry. Further final totals are retained in the increment-7
handoff. Historical attribution and release review remain outstanding.

Reliability checkpoint final source verification: **1489/1489** full suite passed;
the preceding complete run also passed **1488/1488** before BOREL-07 was added.
All ten BOREL barrier/availability tests passed together **10/10**. `npm run check`,
dependency graph and whitespace checks passed. Temporary logs use the
`/tmp/alpha22-reliability-*` and `/tmp/alpha22-deadline-probes*` prefixes.

### Installed-process timing fixture follow-up

was observed (one earlier implementation run failed only two obsolete version
