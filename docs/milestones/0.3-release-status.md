## Increment 7 status

Platform/Wydgine/WydHosting **0.3.0-alpha.22** carries a bounded BackOffice
deadline/abort admission correction. The historical FrontEnd HTTP LIMIT defect
remains open; see [reliability](0.3-reliability.md). Real Chrome [browser qualification](../backoffice-browser-qualification.md) covers
Gate login/logout, installed roster interaction, responsive/theme and bounded
accessibility-tree/contrast checks. Human assistive-technology checks and full
ADM-01 remain incomplete. [Bounded form/result usability](../backoffice-ui-usability.md)
adds recursive array controls and accessible errors. The independent
[operational-notices package](../../examples/backoffice-notices/README.md) uses
canonical Store query with its own permission/receipt, alongside the Gate roster.
Neither module exposes native lifecycle or policy approval.

## Wydgine 0.3 migration path

Continue the five-site goals using standalone Wydgine deployments: independent Node
processes, separate OS users, separate secrets and separate storage behind a
conventional reverse proxy. Do not use shared tenant workers or the experimental
privileged hosting lifecycle as evidence that this path is qualified. These are
operator-managed deployments, not managed WydHosting certification.

Each future site migration still needs its own reviewed source/data inventory,
canonical service configuration, supported runtime/native closure, ownership and
secret separation, private backend/proxy/origin configuration, functional and
security checks, backup and rollback evidence. Keep source and authoritative storage
ownership explicit. Site changes, account/service/proxy configuration and deployment
require their own authorization; this record begins none of them. The unresolved
HTTP issue must be evaluated in 0.3 reliability/release review, not hidden by hosting
deferral or a later passing test run.

## Hosting qualification and Debian work preserved for 0.4

[I5.6](0.3-I5.6/README.md) remains an incomplete experimental milestone. Retain the
[six work packages](../decisions/0003-defer-managed-hosting-qualification-to-0.4.md#six-security-work-packages-retained-for-04),
original gate table, security contracts, installed acceptance criteria and all
passing/failing evidence. Applicable managed migration/recovery and integrated
qualification requirements in I5.7/I5.8 remain prerequisites for managed-hosting
claims; the standalone 0.3 migration path does not satisfy them.

The [Debian feasibility report and VM plan](0.3-I5.6/recovery-and-debian-feasibility.md)
are retained for 0.4. Debian remains a supported target, with no new tested or
security-qualified claim. No VM creation, guest change, installation or policy
experiment is authorized. No version, implementation or security standard changes
are implied by this scheduling decision.
